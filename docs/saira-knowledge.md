# Saira's curated app knowledge

This document describes the repository and limited test evidence, not a guarantee about every installed app or deployment. It must be reviewed for each release. If asked about a capability in a particular installation, do not assume an experimental feature is enabled. Do not claim a signed production APK or a released Android or iOS app exists.

Chatbox is an early mobile-friendly web prototype built with JavaScript, Vite, CSS and Firebase Authentication, with an Android wrapper. The interface includes a Messenger-inspired conversation list, conversation and details views. The default sample conversations and scripted offline Saira guide are demos, not real people or AI. The offline guide works without an AI provider. Search in the live chat prototype filters already loaded conversations by peer name or ID; it does not search all users or messages.

A diagnostic Android debug APK was built previously. The owner reported installing it and signing in with Google. In a separate Firebase test project, the owner also reported exchanging test messages on two phones. This is limited, owner-reported evidence, not comprehensive device testing or a production release. A newer test APK has a different debug signing certificate and its sign-in and update behavior have not been confirmed. Debug APKs are not production-signed releases.

A two-person Firestore chat prototype is disabled by default in the source. A two-account-restricted combined admin, chat and call ruleset was deployed to the isolated test project only, and its release was read back. Real-device behavior has not been validated. Do not imply the production chat is enabled. The test rules let anyone read settings/public and the bounded public appearance and welcome settings, do not stop other users signing in, and are not an independent security review. The chat is not end-to-end encrypted. Profile names are unverified; under the candidate rules any allowed signed-in account that knows a UID can look up that profile. Use only synthetic data in test projects. Recent-message pagination, consent and blocking have simulated tests; real-world privacy, abuse prevention and device behavior remain incomplete. A pending offline write may still succeed later, so an unknown outcome should be checked before retrying.

Voice and video calls are not available in the default app or deployed production site. A separate default-off browser lab and an isolated Android debug-only call experiment have local microphone and camera controls, but the Android experiment is unverified and not for release. A two-account rules candidate was deployed to the isolated test project after simulated emulator checks; actual calls over real networks have not been validated. Optional Google STUN shares the user's IP address with Google and network addresses may be visible to the peer; STUN is not a TURN relay and some networks will not connect. There is no configured TURN, background calling or notification system. Muting suppresses outgoing content but does not revoke permissions or guarantee that device capture stops; ending the call stops local tracks. Page lifecycle and disconnection handling are best-effort and can be delayed. The lab lacks production security review, quotas, automatic cleanup and verified real-device behavior.

The admin studio is locked by default. An experimental Spark-compatible admin prototype supports previewed public welcome text, a bounded home color and mobile menu position, and owner-managed delegation. A restricted rules candidate was deployed only to the isolated test project; the feature is disabled by default, has not been verified on a real device, and is not a general AI administrator. It has no complete audit history. A separate proposed server backend also supports limited reviewed actions, not arbitrary code or deployments. Neither prototype is a production authorization or security review.

Full Saira AI is not connected in the default app. Experimental Firebase AI Logic and server-side AI paths need project configuration, App Check and real-service validation. The isolated Android debug build contains a native Firebase AI and Play Integrity bridge, but live behavior has not been verified. The isolated Firebase AI App Check is enforced. For the isolated Android test app only, Play Integrity now allows off-Play app versions; device integrity, certificate registration and actual AI behavior still need verification. Questions sent to an AI provider may contain personal information; do not send sensitive content. Model answers may be inaccurate. Do not expose API keys or imply these experiments are active in production.

Separate experimental message and request cooldown candidates have simulated emulator tests but are disabled, undeployed and not comprehensive abuse protection. Multiple accounts and repeated requests after the interval remain possible. They require matching rules and client flags, security review and real-device tests, and may incur additional Firestore reads and writes.
