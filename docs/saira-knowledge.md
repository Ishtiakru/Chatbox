# Saira's curated app knowledge

Chatbox is an early mobile-friendly web prototype built with JavaScript, Vite, CSS and Firebase Authentication. An Android wrapper exists and an incomplete diagnostic debug APK was built in Cloud Shell, but it has not been tested on a device; there is no released Android or iOS application. The provided Chatbox logo appears in the app.

The existing published version has sample conversations stored only in the browser and an offline scripted Saira guide. Sample profiles are not real users. Google sign-in has been configured in code but still requires end-to-end testing.

The repository contains an experimental two-person Firestore chat behind an off-by-default feature flag. Its recent-message window and older-history pagination have local simulated tests; cache can be incomplete and real-account and phone tests remain outstanding. The selected peer’s user-provided display name is explicitly marked unverified. Any signed-in user who knows a UID can directly look up that profile under the experimental candidate rules, even without a conversation; this is not private profile storage. It is not deployed or ready for production, is not end-to-end encrypted, and has an experimental recipient-acceptance flow. A previous combined candidate passed 23 simulated tests in the official local emulator; the changed rules need another official-emulator run. The system still needs independent security review, real-project testing, anti-abuse safeguards, and production-ready user blocking. A default-off blocking lab has experimental user controls but is undeployed, not officially tested, and cannot reliably stop already-connected calls on other devices. Closing one conversation does not block future requests. A third-party emulator smoke test has also passed; neither test is a complete security review. A PWA installation manifest and offline notice have been smoke-tested locally but have not been deployed. Offline chat is not provided.

Voice calls and video calls are not connected in the default app. The separate browser-only experimental call lab is not deployed; it has local microphone and camera toggles and best-effort connection setup and disconnection timers. Muting does not revoke permission or necessarily stop device capture; ending the call stops local tracks. Leaving Live chats or hiding the page is intended to end the local call and returning does not automatically resume it. Browsers can delay or miss lifecycle events, and real-device testing is still required. Timers and connection-state events can also be delayed. The admin studio is locked. Experimental AI Logic code for a possible Spark free-tier Saira and server-side code for an AI and a narrowly scoped admin welcome-message update are under development; neither has been deployed. AI Logic requires project setup and App Check; the server Functions approach requires billing. An experimental Spark-compatible candidate supports a verified Google owner inviting and revoking delegates while retaining ownership. It is disabled and has not been deployed or security-reviewed. Its deterministic command parser can only preview a public welcome message using a few exact English or Bengali patterns; confirmation is required, and it is not AI. An experimental button can reauthenticate the same Google account before rechecking the server-side role; it does not grant admin access and has only mocked local tests, not real Google or Android tests. Google sign-in alone does not give admin access.

A separate, default-off experimental message cooldown candidate limits accepted messages to one every two seconds per account across chats and devices in local simulated tests. It is not deployed, is not complete spam protection, may consume additional free Firestore quota, and still requires the official emulator, real-account/device testing and security review.

A separate default-off request cooldown candidate can limit accepted conversation requests to one per sender account every 30 seconds in local simulated tests. It is not deployed or complete spam protection, and requires matching message-cooldown rules and client flags, official emulator and real-device tests, and security review. Multiple accounts and repeated requests after the interval remain possible. Extra writes and rules reads may consume free quota. The experimental chat now checks the peer profile on the server before making a request, so requesting a conversation needs a network connection. Signing out or refreshing does not necessarily cancel an already-pending write; its outcome may remain unknown and should be checked before retrying.

A future AI can answer only from this curated document and should admit when information is missing. No documentation guarantees every code change is reflected automatically. Developers must review this document as part of each release; deployment must also update the backend. Never imply that planned features are active.
