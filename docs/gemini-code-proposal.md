# Experimental single-file Gemini code suggestions

This opt-in, Android test-only prototype loads one public text file from a pinned GitHub commit and shows it to an authorized Spark dashboard user. Only the explicit "Send request and file to Gemini" button sends the current prompt and reviewed file to Firebase AI Logic (Gemini Developer API). The UI displays an escaped untrusted response; it can be copied for manual review. It does **not** edit the repository, run code, run tests, create a PR, rebuild or deploy. AI can be wrong, malicious, incomplete or truncated. This is not an implementation of arbitrary automatic code changes or a trusted coding agent. A multi-file change cannot reliably be handled with one file. The user must know the relative file path and the source is limited to 24 KB. Files from the build snapshot may be outdated by the time the proposal is reviewed.

No source archive or repository credential is included in the APK. Only allowlisted public text paths are fetched from the public Ishtiakru/Chatbox repository through GitHub's public API; requests may fail due to network, rate limits, snapshot or CORS. The client cannot fetch private or uncommitted files. The selected file and prompt are sent to Google; free-tier terms may permit use for service improvement. Never include secrets, private messages, personal data or proprietary code. Clipboard contents can be visible to other apps. This UI gate is not an authorization boundary; attestation, quota controls, account authorization and abuse protection need independent review. Real Android sign-in, Play Integrity, source fetch, Gemini model response and clipboard have **not** been verified.

`VITE_ENABLE_CODE_PROPOSAL_LAB` is default off and gated behind the already isolated Android AI lab; the test APK workflow pins `VITE_CODE_PROPOSAL_REF` to its exact GitHub commit. No free availability or quota is guaranteed. The result is not applied after confirmation: a secure future automatic pipeline still needs authoritative authorization, a least-privilege repository integration, isolated credential-free build/test sandboxes, audit, abuse protection and owner approval. Do not put a GitHub token or AI secret in the application.
