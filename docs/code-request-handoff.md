# Manual code-request handoff (isolated test only)

This is not an automated code editor or release pipeline. When explicitly enabled for the isolated Spark test build, an authorized dashboard user can copy a request in any language, paste it into an Arena agent conversation with repository access, and ask the agent to make and test a change. The app does not send the request, receive a status, modify code, create a PR, build an APK or deploy. The external agent's language support, service limits and access are not guaranteed. The copied text can be visible to other apps; never include secrets, private messages, tokens or personal data. GitHub repository Ishtiakru/Chatbox is public: commits, PRs and issues can be publicly visible. Review proposals and release actions separately.

The local build flag `VITE_ENABLE_CODE_REQUEST_HANDOFF` is off by default and requires `VITE_CHATBOX_TEST_MODE` and Spark admin. This is a convenience view, not an authorization boundary and not a secure backend. The current test APK workflow enables it; an APK must be rebuilt to include it. Auth, Android clipboard, App Check, real-device use and external service availability still need verification.

A genuinely automatic free-tier code-editing pipeline is not configured. Such a system would need verified per-user server-side authorization, a restricted queue, protected GitHub integration, isolated builds without credentials exposed to proposed code, review, rate limits, monitoring, private-data handling, and separate release approval. Free quotas and third-party availability can change; no unlimited free service is promised.
